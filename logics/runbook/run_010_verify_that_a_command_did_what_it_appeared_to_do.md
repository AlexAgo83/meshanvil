# Trigger
- An agent is driving work through a shell, and the next step depends on the previous one having done what it said.
- A conclusion is about to be drawn from a command's output: "nothing was found", "it did nothing", "the platform does not support it".

# Prerequisites
- Know which shell is actually interpreting the line. On macOS an interactive agent shell is usually zsh, and zsh differs from bash on exactly the cases below.
- Know how many shells a remote command crosses. Four is normal for a Windows host with WSL: local shell, ssh, `cmd.exe`, then `bash -lic`.

# Procedure
1. **Make every destructive or preparatory step print a proof line.** Not the command's own output: a separate observation of the state it was supposed to produce. `rm` then `ls | wc -l`. A cleanup nobody verified is a cleanup that may not have run.
2. **Never let a glob be the only thing standing between you and a wrong conclusion.** In zsh a pattern that matches nothing aborts the whole command line with `no matches found`, so `rm -f a/*.x b/*.y` deletes nothing at all when only the second pattern is empty. Use `find <dir> -name '<pattern>' -delete`, which is silent on zero matches and identical on both shells.
3. **Do not pipe a command whose exit code you are about to read.** `cmd | grep x; echo $?` reports grep's status, not the command's. Run it, read `$?`, then filter separately.
4. **Quote every variable, and assume no word splitting.** zsh does not split an unquoted parameter into words, so `$cmd` holding `run op file` is passed as one argument. A loop built that way produced four exit codes of zero in a tenth of a second and looked like four successful runs.
5. **Through more than two shells, inline the value instead of naming it.** A variable expanded across ssh, `cmd.exe`, `wsl.exe` and `bash -lic` collapsed to empty, so the command ran as `"" --version`. The conclusion drawn -- that the Windows binary does nothing when called from Linux -- was false, and the retest with the path written literally worked on the first attempt.
6. **Check the regex dialect before trusting a gate that found nothing.** `git grep -E` is POSIX ERE, where `\b` is undefined: a word-boundary anchor silently matches nothing on macOS. Spell edges out as `(^|[^A-Za-z])` and `([^a-z]|$)`.
7. **Test a gate in both directions, every time.** Feed it a line that must fail and confirm it fails, then remove the line and confirm it passes. A gate that has only ever returned "clean" has not been shown to be a gate.
8. **A check that cannot pass in its own harness is not proof the thing it checks is broken.** A headless-Chrome smoke asserting on `navigator.clipboard.writeText` and on `document.execCommand("copy")` got `NotAllowedError: Document is not focused` and `execCommand=false` from both, on a feature that works the moment a person clicks it in a real, focused tab. The env lacks focus and clipboard permission by construction, not because the code regressed. Assert what the harness can actually prove -- the button exists, is a real `<button>`, and clicking it never throws -- not the part of the behaviour the harness cannot grant.
9. **`--virtual-time-budget` is not a reason to drop it against a live server -- it is why the timers waiting on that server's response ever fire.** A smoke against a real `--serve` subprocess omitted the flag on the theory that virtualised time would fight a real network round trip; `--dump-dom` then returned the page exactly as it loaded, before the click handler's `fetch` had a chance to resolve, because Chrome dumps at the load event and does not wait for pending JS timers on its own. The flag does not block real sockets, it advances the clock so the `setTimeout` polling loop waiting on the response actually runs before the dump. Verified by adding it back at 5s and watching the same assertion pass.
10. **A passing unit check on the rule is not evidence the artefact built from it works.** Four checks over a viewer's grouping rules passed against the project's real data -- the right chains, the right names, the orphan correctly flagged -- while the page itself drew one node instead of nine. The rules were right; the layout that consumed them ran once at load and never again, so every chain but the first was positioned at `left:undefined` and the nodes stacked in the corner. Nothing in the pure checks could see that, because none of them rendered anything. Open the artefact, or assert on the rendered result, before reporting the work done.
11. **A fixture with one of something proves nothing about the rule that groups them.** The same viewer's browser smoke passed throughout, because its demonstration project has exactly one chain start -- and with one start, "each start gets its own group" and "the canvas draws only the selected start's chain" are true by construction. The regression became visible the moment the fixture carried a second start, and the assertion that catches it is one line: the drawn nodes must occupy as many distinct positions as there are nodes. Count the axis your rule discriminates on, and make sure the fixture has at least two.
12. **A render that succeeded is not a render that shows the subject.** `render_subject` reported ok, listed four views, and every file existed at the path the report named -- and all four had the hammer cropped at both ends. The camera sized its orthographic width from the bounding diagonal, but `ortho_scale` sizes the *long* sensor axis, so on a 1200x760 frame the visible height is 0.63 of it: a 432 mm subject was given 352 mm of height. Nothing could catch this except looking, because a wide subject -- every vehicle this project had rendered until then -- never hits it. Framing is now computed from the subject projected onto each canonical direction, one width for all views so a before/after wipe stays comparable. The same view carried a second version of the same fault: looking straight down leaves `to_track_quat` free to pick any up vector, and it picked one that put every plan on a 45 degree diagonal -- passable on a car, useless for judging a footprint. Straight down is the one direction whose roll has to be stated.
13. **A render that shows nothing at all is the same failure with none of the tells.** `render_subject` reported ok on a CAD assembly, wrote five files, and every one was an empty grey frame -- and every number in the report was correct: 2339 solids, 8.8 M vertices, a bounding box that matched the source. The camera stands back at four radii, and its clipping was still Blender's 1000 unit default, so a subject arriving in millimetres -- 2780 units across -- sat entirely behind the far plane. The measurements cannot catch this by construction: they measure the geometry, and the geometry was fine. Only opening the image does. It is also the reason a demonstration that only ever renders metre-scale subjects will never see it: the fixture box, 40 units, rendered perfectly throughout.
14. **A command that has not returned is not a command still working.** A `meshanvil run` on a FreeCAD operation sat for ten minutes with no output. The operation had in fact finished in 0.12 seconds: the report was written, complete and correct on disk the whole time. `FreeCAD -c` drops into an interactive console when its script ends, and with a terminal still attached it waits there for a Ctrl-D that never comes. Two things were wrong, and only one of them was FreeCAD's: the engine's stdout and stderr went to `/dev/null`, so there was nothing to look at and no way to tell working from hung. Give a headless engine no stdin, and give its output a log -- the very next failure after that change was a `NameError` on line 232, named in one line, on a run that would otherwise have said only "the engine wrote no report".
15. **A page served from a copy is not the page you just built.** `meshanvil view` writes the viewer into the project, and a running server goes on serving that copy: every change to the viewer since it started had reached nobody, and the live stream -- which had just been taught to watch the bundle and reload -- was watching a file nothing was updating. The feature worked and could not fire. Then the same fault at one remove: the copy was refreshed, the page reloaded, and it came back with new behaviour and the *old layout*, because the cache-buster was on the script and not on the stylesheet. Half a rebuild is harder to recognise than none of it: the feature is there, it just looks broken.
16. **An assertion bound to a position breaks on a change that is not about it.** A browser smoke asked for the first `[data-note-kind]`, matched chain headers by the word "Chain" in their text, and counted `<option>` elements. Three unrelated changes -- swapping two panels, dropping a label prefix, replacing a `<select>` -- each broke it, and none of them broke the thing being tested. Ask by meaning: the field of kind `reports`, the header that carries the fold class, the rows the list actually renders.
17. **A script that never ran reports nothing at all, and that is the tell.** An injected smoke declared `const cards` where an earlier line already had -- a duplicate declaration is a syntax error, so the whole script failed to parse and neither the pass nor the fail branch ever executed. The dumped DOM held no result element of either kind. A harness that reports neither success nor failure has not failed a check; it has not run. Look for the absence of the marker, not for the failure message.
18. **A default that is filled in on every run overrides the thing that was measured.** A generator took its dimensions from a plan "unless the operator asked for others", and the operation manifest declared defaults of 2695 x 1663 x 1555 -- inherited from a different subject. The runner fills a default on every run, so the plan's 2700 was silently replaced and the report stated a size nobody had chosen and no view had been read at. Make the sentinel mean absence: zero, or no key at all, and never a plausible number.

# Verification
- After a cleanup: count what remains, do not assume. `ls work/ops/*.json | wc -l`.
- After a remote command: read something written on the far side, not the exit code. A command that never ran and a command that ran without effect both exit 0.
- After changing a pattern in a check: run the corpus of known positives past it. Four out of five caught is a failing pattern, and only an explicit list shows which one escaped.
- When a measurement contradicts an action that was supposed to change it: suspect the measurement first. In Blender, `object.bound_box` is a cache that stays stale until the depsgraph updates, and reading it after a mesh edit reports the geometry from before the edit.
- Before asserting on a browser API in a headless smoke: check what the harness itself can grant (focus, permissions, a real user gesture) and assert only up to that boundary.
- Before dropping a Chrome timing flag against a live server on a theoretical conflict: try it with the flag first. `--dump-dom` proves nothing about work still pending in a timer when the dump was taken without one.
- After changing anything that renders: open the image, do not just check that the operation reported ok and the file exists. A path that resolves says nothing about what is inside it.
- After changing anything a page renders: dump or screenshot the page itself, on the real data, and look at it. Reason about the rule if you like, but report only what the artefact showed.
- Before trusting a fixture: check it contains at least two of whatever the rule distinguishes. A one-of-a-kind fixture satisfies most grouping and selection rules without exercising them.

# Rollback
- Nothing here writes. The cost of the mistakes is wasted reasoning, and the recovery is re-running the step with a proof line attached.

# Limits to state, not to hide
- These are the traps met in one session on one machine; the class is larger. The transferable rule is the one they share, not the list: **a command that printed nothing is not a command that found nothing.**
- Proof lines cost a round trip each. On a tight loop, verify at the boundaries -- after a cleanup, before a conclusion -- rather than after every step.
- An agent that adds a proof line to every command becomes unreadable. The discipline applies to steps whose failure would be silent, which is a much smaller set than "all of them".
